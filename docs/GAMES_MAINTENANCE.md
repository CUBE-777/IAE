# وضع صيانة قسم الألعاب (migration 0062)

**الإعداد:** `site_settings.games_section_status` ∈ `enabled | maintenance` (لا جدول جديد). يُغيَّر من `/admin/settings` ← «حالة قسم الألعاب» (super_admin + developer فقط، والحدّ الفعلي RLS + مشغّل تحقق).

**ترتيب النشر:** (1) نفّذ `supabase/migrations/0062_games_maintenance_mode.sql` (جرّب أولًا بـ `rollback;` بدل `commit;`)، (2) شغّل `supabase/tests/games_maintenance_smoke.sql` على بيئة تجريبية، (3) انشر الواجهة. الواجهة المنشورة قبل 0062 تعمل كالسابق (الألعاب مفعّلة) ويظهر في الكونسول تحذير فقط.

**الحماية:** `can_access_games()` (التي تستعملها كل سياسات RLS ودوال RPC اللاعب 0050–0061) ترفض الجميع أثناء الصيانة. `can_manage_games()` مستقلة عنها فتبقى إدارة الألعاب تعمل. كل مسارات `/games/*` تمر عبر `GamesLayout` الذي يعرض صفحة الصيانة قبل أي حارس أو صفحة.

**التزامن:** Realtime على صف المفتاح + مؤقّت 45 ث (أثناء ظهور التبويب فقط) + إعادة الجلب عند العودة للتبويب/الاتصال. مثيل واحد مشترك (جلب واحد وقناة واحدة) ولا يعمل إلا حيث تُفتح الألعاب أو الإعدادات.

**الرجوع:** `supabase/rollback/0062_games_maintenance_mode_down.sql` (يعيد 0049/0052 حرفيًا؛ إن كانت الصيانة مفعّلة لحظتها فتُفتح الألعاب).
